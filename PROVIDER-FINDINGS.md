# Provider validation — 2026-10-12

Verified official machine-readable schemas at https://api.henrikdev.xyz/openapi.json and the documentation index at https://docs.henrikdev.xyz/llms.txt. The documentation site's own `/api-reference/openapi.json` unexpectedly served a sample plant schema; the provider-hosted spec is the authoritative schema used here.

- Authorization uses the HenrikDev key directly in the `Authorization` header. Never send it in a query string.
- Older v1 MMR history, v3 matches, and v2 current MMR remain listed in the spec. Prefer account v2 lookup, v4 PUUID matches, v2 PUUID MMR history and v3 PUUID current MMR. PUUID is stable across Riot ID changes; initial resolution is cached one hour.
- Live v4 match history: `/valorant/v4/by-puuid/matches/{affinity}/{platform}/{puuid}?mode=competitive&size=10&start=0`. `start` is zero-based; size is capped at ten. Metadata supplies `started_at`, `game_length_in_ms`, `is_completed`, `match_id`, and `queue.id`. Players expose `team_id`; teams expose `won` and round counts. These are validated at runtime; unrelated fields may be added without breaking parsing.
- MMR history: `/valorant/v2/by-puuid/mmr-history/{affinity}/{platform}/{puuid}`. `data.history` supplies `match_id`, `date`, `last_change`, tier and optional placement flag. No pagination is documented for this live endpoint. Unknown placement flags are treated conservatively. Stored MMR pagination cannot certify complete live history.
- Current MMR: `/valorant/v3/by-puuid/mmr/{affinity}/{platform}/{puuid}`, reading `data.current.tier.name`, `rr`, and `games_needed_for_rating` rather than past match rank.
- Individual v4 details: `/valorant/v4/match/{affinity}/{match_id}` returns `{status, data}` with the same match schema as v4 history items. Used to fetch only missing update IDs after the live traversal boundary is verified; validated match IDs must agree with the request.
- [Stored-history guide](https://docs.henrikdev.xyz/valorant/guides/stored-matches): `page` is one-based with `size`; totals count stored records only. Failed or never-requested match details can be omitted silently. Do not use this as coverage proof.
- [Rate limits](https://docs.henrikdev.xyz/general/rate-limiting): limits are per key, include background Riot requests, and expose cooldown headers. Exact quota depends on plan.
- [Twitch Get Streams](https://dev.twitch.tv/docs/api/reference/#get-streams) accepts an app token with `Client-Id` and `Authorization: Bearer ...`. Empty `data` means offline. `started_at` is the active stream's UTC start, and `id` identifies its session. No category filter is applied.
- [Twitch client credentials](https://dev.twitch.tv/docs/authentication/getting-tokens-oauth/#client-credentials-grant-flow): POST client ID/secret and grant type to `https://id.twitch.tv/oauth2/token`; use `expires_in` and reacquire on expiry. No refresh token is required for this grant.
